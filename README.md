# LigthingControl

Единое управление лампочкой Яндекса и BLE RGB-лентой (аналог "Lotus Lantern") из одного места,
включая режим динамической подсветки по цвету экрана (амбилайт).

## Возможности

- `set-color R G B` — задать один и тот же статичный цвет сразу на лампочке и на ленте.
- `power on|off` — включить/выключить оба устройства одной командой.
- `ambilight` — непрерывно захватывать экран, вычислять текущий цвет (среднее или доминирующий)
  и синхронно отправлять его на оба устройства с настраиваемой гаммой, яркостью и сглаживанием.

## Архитектура

```
screen (mss) -> color.py (среднее/доминирующий цвет, гамма, сглаживание)
                     |
                     v
              controller.py (рассылает цвет во все включённые устройства параллельно)
                 /              \
                v                v
   devices/yandex_bulb.py   devices/rgb_strip_ble.py
   (Yandex IoT HTTP API)    (Bluetooth LE, протокол Triones)
```

Каждое устройство реализует общий интерфейс `LightDevice` (`connect`, `set_color`, `set_power`,
`close`), поэтому включить/выключить любое из них — это просто `enabled: false` в конфиге.

## Требования

- Windows 10/11.
- Python 3.10+ с [python.org](https://www.python.org/downloads/) (при установке отметить
  "Add python.exe to PATH").
- Bluetooth-адаптер (встроенный в ноутбук или USB-донгл) с установленными драйверами —
  BLE-часть работает через стандартный Bluetooth-стек Windows, ничего дополнительно ставить
  не нужно.

## Установка

В PowerShell или cmd, из папки с репозиторием:

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy config.example.yaml config.yaml
```

Если PowerShell блокирует активацию скриптом (`не удаётся загрузить... не имеет цифровой подписи`),
выполните один раз: `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass`, затем повторите
`.venv\Scripts\activate`.

`config.yaml` в `.gitignore` — токены и MAC-адреса туда не попадут в git.

## Настройка лампочки Яндекса

Управление идёт напрямую через официальный HTTP API "Умного дома" Яндекса
(`https://api.iot.yandex.net/v1.0`), тот же самый, которым пользуется Алиса и мобильное
приложение — в обход Алисы, без голосовых команд.

1. **Получить OAuth-токен.** Нужно приложение, зарегистрированное на https://oauth.yandex.ru
   с доступом к разделу "Умный дом" (в консоли разработчика Яндекса — Yandex OAuth App с
   правами на `iot:*` / smart home). Проще всего это делают через уже существующие открытые
   интеграции (например, компонент Yandex Smart Home для Home Assistant) — если вы уже
   настраивали умный дом Яндекса в Home Assistant или похожем проекте, токен оттуда подойдёт.
   Официальная документация с описанием процесса авторизации:
   https://yandex.ru/dev/dialogs/smart-home/doc/concepts/access.html
2. **Узнать device_id.** С полученным токеном выполните в PowerShell:
   ```powershell
   Invoke-RestMethod -Uri "https://api.iot.yandex.net/v1.0/user/info" -Headers @{Authorization="Bearer <ВАШ_ТОКЕН>"} | ConvertTo-Json -Depth 10
   ```
   В ответе будет список ваших устройств (`devices[].id`, `devices[].name`) — найдите
   нужную лампочку и скопируйте её `id`.
3. Впишите оба значения в `config.yaml` → `yandex.oauth_token` и `yandex.device_id`.

Цветовая модель (`rgb` или `hsv`) определяется автоматически при подключении — код
сам смотрит на `color_setting.parameters.color_model` устройства и шлёт нужный формат.
Если у лампочки капабилити `color_setting` вообще нет (только вкл/выкл) — `set-color`
для неё тихо пропускается, а `power`/`ambilight` по вкл/выкл продолжают работать.

## Настройка RGB-ленты (BLE)

Проект поддерживает два готовых протокола, покрывающих большинство generic Bluetooth
RGB-контроллеров под разными брендами/приложениями (включая, как оказалось на практике,
и часть лент под Lotus Lantern):

| `protocol` в config.yaml | GATT-сервис | Характеристика для записи |
|---|---|---|
| `triones` (по умолчанию) | `0000ffd5-...` | `0000ffd9-0000-1000-8000-00805f9b34fb` |
| `happy_lighting` | `0000fff0-...` | `0000fff3-0000-1000-8000-00805f9b34fb` |

1. **Найти MAC-адрес ленты.** С телефона — приложением **nRF Connect** (Nordic Semiconductor,
   Android/iOS): при сканировании оно покажет MAC и GATT-характеристики устройства. С компьютера —
   входящим в репозиторий скриптом (виртуальное окружение должно быть активировано):
   ```powershell
   python scan_ble.py
   ```
   Он 10 секунд ищет BLE-устройства поблизости и печатает их MAC-адреса и имена.
2. **Определить протокол.** Узнайте реальные сервисы/характеристики устройства:
   ```powershell
   python list_ble_services.py <MAC_адрес>
   ```
   Если среди характеристик есть `0000ffd9-...` — используйте `protocol: triones`. Если
   `0000fff3-...` — `protocol: happy_lighting`. Впишите оба значения (`mac_address`,
   `protocol`, `write_characteristic_uuid` из таблицы выше) в `config.yaml`.
3. Убедитесь, что телефон с приложением Lotus Lantern в этот момент **не подключён** к ленте —
   BLE-устройство одновременно держит только одно активное соединение.

### Если ни один протокол не подошёл

Проверьте формат вручную, отправляя произвольные байты напрямую на характеристику:
```powershell
python send_raw.py <MAC_адрес> <UUID_характеристики> "7E 00 05 03 FF 00 00 00 EF"
```
Меняйте байты и смотрите на реакцию ленты. Если найдёте рабочую комбинацию для цвета
и отдельно для вкл/выкл — откройте `unified_lighting/devices/rgb_strip_ble.py` и добавьте
новую запись в словарь `PROTOCOLS` по образцу уже существующих (`_triones_color`/
`_happy_lighting_color` — примеры функции сборки цветовой команды).

Если и подбором ничего не находится — остаётся перехватить реальный трафик от Lotus Lantern:

1. На Android включите Параметры разработчика → "Журнал захвата Bluetooth HCI"
   (Bluetooth HCI snoop log).
2. Откройте Lotus Lantern, несколько раз измените цвет и включите/выключите ленту.
3. Выключите захват, найдите файл `btsnoop_hci.log` (обычно в `/sdcard/` или через
   "Отправить отчёт об ошибке"), откройте его в Wireshark.
4. Отфильтруйте по `bthci_acl` и найдите пакеты записи (Write Command/Request) в GATT —
   в них будут байты, которые приложение реально отправляет на характеристику.
5. Добавьте найденный формат в `PROTOCOLS`, как описано выше.

## Запуск

```powershell
# статичный цвет
python -m unified_lighting set-color 255 80 0

# включить/выключить оба устройства
python -m unified_lighting power on
python -m unified_lighting power off

# динамическая подсветка по цвету экрана (Ctrl+C для остановки)
python -m unified_lighting ambilight
```

По умолчанию используется `config.yaml` из текущей директории; другой путь — через `--config`.

## Настройки режима ambilight (`sync` в config.yaml)

| Параметр              | Смысл                                                              |
|-----------------------|---------------------------------------------------------------------|
| `fps`                 | Частота опроса экрана и отправки цвета                              |
| `color_algorithm`     | `average` — среднее по кадру; `dominant` — грубая оценка доминирующего цвета |
| `brightness`          | Множитель яркости 0.0–1.0                                            |
| `gamma`               | Гамма-коррекция (делает средние тона визуально ярче)                 |
| `smoothing`           | 1 = мгновенно (без сглаживания), ближе к 0 = медленнее/плавнее (меньше мерцания) |
| `min_change_threshold`| Не слать обновление, если цвет изменился меньше чем на эту сумму |Δr|+|Δg|+|Δb| — экономит трафик и продлевает жизнь BLE-соединению |
| `monitor_index`       | Какой монитор захватывать (нумерация `mss`, `1` — первый)             |

Можно включить только одно устройство, отключив второе через `enabled: false` в
соответствующей секции конфига — например, чтобы сначала проверить ambilight только на ленте.

## Тесты

Протокольная логика (упаковка RGB для Яндекса, байты команд для BLE-ленты, обработка цвета
кадра, гамма, сглаживание) покрыта юнит-тестами, не требующими реального оборудования:

```powershell
pip install pytest
pytest
```

## Известные ограничения

- Протокол BLE-ленты (`triones`) — это распространённый отраслевой стандарт для подобных
  контроллеров, но не гарантированно тот же самый, что использует именно ваша модель под
  Lotus Lantern. Если не заработает сразу — см. "Если протокол не подошёл".
- Захват экрана (`mss`) требует активной сессии с монитором — на Windows это не проблема при
  обычном запуске, но не заработает, например, через удалённую сессию без активного дисплея.
